# 自動受け取り

**既定でオンです。** 普通に入室・着席し、サーバーがタスク完了を確認したあと、Web のバックグラウンドが受け取ります。着席・部屋移動・ギフト・課金・会員・共有は代行しません。ページを閉じたあとも通常タスクとチェックインは確認できますが、ルーム宝箱には Web 側の本物で未期限切れの通常入室セッションが必要です。試聴では受け取れません。

## 対象

- **個人／イベント／実績タスク：** 公式タスクページから動的に見つけ、`status=1` の報酬を受け取ります。着席1回のシルバー、別ホスト2部屋のシルバーとギフトなど。受け取るだけで、タスク行為は実行しません。
- **リスニング7日チェックイン：** 公式の累計滞在と `sign_status=0` で受け取ります。ローカルタイマーから資格を推測しません。
- **段階ルーム宝箱：** いま入室しているアカウント、部屋タスク進捗、部屋レベル、在庫、`can_receive=1` が揃ったときだけ。1段階拒否されても後続は試します。1回だけ受け取り、別入口が必要なアイテム箱は自動では開きません。
- **旧タスク：** シルバー任務、旧サイン、サーバーが無料と印したガチャ、既存の毎日いいね枠。成長タスク `type=2` はそのまま渡し、0 に潰しません。
- **広告：** 公式 `adNotification` の残り回数でバックグラウンド `finishedADEncryptV2`（`ad_point`、1周最大5回）。`lotteryInfo.is_free` のときだけ `ad_draw`。AppLovin プレーヤーはありません。

入室／席の変化から約 1.5〜3 秒後に確認し、在室中は10秒ポーリング。チェックインは30秒、イベント／実績は60秒、部屋の外は60秒。公式進捗の遅れは次の「受け取れる」応答に従い、ゼロ遅延は約束しません。新旧入口が進捗を共有する場合は公式状態で重複を除き、重ね取りは約束しません。

ページ上部の「自動受け取り」を開くと、滞在進捗、タスク、宝箱が受け取れない理由、最近の結果が見られます。箱の中身表示は賞池であり必得ではありません。`errno=0` でも内側が拒否、または結果不明なら成功とは出しません。

## 重複防止と失敗

- 新しい経路の永続状態は状態ボリュームの `rewards-state.json`（権限 0600）。ログイン身分で隔離し、日界は日本時間。同じホストの日宝箱は退室・部屋替え・更新では再取得しません。
- リクエストの前に原子的に pending ログを書いて同期します。ネットワークタイムアウトは先に公式の受取済みを照合。最低2分待ち、再び受け取れる状態を読んでから同じ報酬を再試行できます。保存破損や書き込み失敗ではリクエストを止め、台帳を空にしてやり直しません。
- 単一プロセス、キューから出す前にログイン身分と宝箱の部屋権限を再確認。退室、リース期限切れ、アカウント切替、停止のあとに古い部屋の受け取りは出しません。
- 新しい経路は1周最大12回、1日最大200回（失敗も数える）。権限／電話番号制限は理由を残してバックオフし、条件は迂回しません。

`/api/tasks/auto` の総スイッチと `GRAVITY_TASKS_SYNC=0` を使います。`/api/tasks/status` はローカルスナップショットだけで、閲覧は受け取りを起こしません。

モック通過は実受け取りの代わりになりません。最終確認は公式残高／バッグです。署名バージョンは `UPGRADE_REVIEW.md`。
